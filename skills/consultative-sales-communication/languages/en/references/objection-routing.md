# Objection routing

Restate what was said, distinguish a condition, missing information, risk,
alternative or refusal, then address the main concern with one optional next step.
Emotion needs acknowledgment; facts need verification; process needs roles and
checkpoints; an explicit boundary needs respect.

| Customer statement | Response direction |
|---|---|
| Too expensive | Clarify comparable configuration/service/tax/delivery or target budget |
| Busy | Close briefly; for a relevant existing matter ask permission for a later checkpoint |
| I'll contact you if needed | Close; no appended pitch or meeting request |
| We rarely buy hardware | Recognize their focus; describe optional relevant support without assuming demand |
| We have a supplier | Respect that relationship; consider backup use only if invited |
| Not my responsibility | Clarify role and a voluntary introduction path |
| Delivery won't work | Confirm the hard requirement and verify options; do not promise feasibility |
| No reply | Wait unless there is new value or an agreed checkpoint |

Do not assign a follow-up date unilaterally when the customer is busy.
Do not attack competitors, instantly discount, or make up urgency.
Stop if continuing requires invented facts, unauthorized commitments or bypassing procurement.
Repeated weak responses do not cancel existing service/delivery duties.
