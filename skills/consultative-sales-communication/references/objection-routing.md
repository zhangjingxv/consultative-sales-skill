# 异议路由

## 使用顺序

1. 原样确认客户说了什么。
2. 区分真实条件、信息缺口、风险顾虑、替代方案或礼貌拒绝。
3. 只处理当前最主要的一项。
4. 给一个可拒绝的小下一步；若客户已明确拒绝则直接收束。

## 价格高

先问清比较对象：同一配置、同一服务、同一税务口径、同一交付条件，还是预算本身不足。

```text
明白，您现在主要卡在总价。
我先把配置和服务口径跟您对齐，看看差异是在硬件、服务还是交付条件；您方便把对比口径或目标预算发我一个吗？
```

不要立即承诺降价，不贬低竞品，不编造“最后一天”。

## 最近忙

第一次：承认时间压力，降低动作成本，给一个更晚且具体的节点。

```text
明白，您先忙项目。我下周二再跟您确认一次，到时只占您几分钟把需求边界对一下。
```

再次含糊：停止推进。

## 有需求再找你

视为当前无明确下一步。简短收束：

```text
好的X总，那我先不打扰。后面有服务器、存储或网络设备配置和报价，您把需求发我，我及时配合。
```

不要紧接着再次约访。

## 很少做硬件

不争辩。判断是否存在偶发配套价值：

```text
明白，您这边还是以软件／服务项目为主。后面偶尔碰到服务器、存储或网络设备配套，我可以帮您补配置和报价这一段。
```

只有客户继续问或提供项目事实时再推进。

## 已有固定供应商

先尊重已有关系，再确认是否存在补位场景：紧急交期、特殊配置、第二询价、异地交付或品牌覆盖。

```text
明白，固定供应商用得顺最重要。我这边先不替换您现有合作；以后遇到特殊配置、需要第二个报价或交期补位时，可以发我帮您多看一眼。
```

不要攻击或暗示现有供应商不可靠。

## 不是我负责／需要问领导

本轮目标是识别角色和自然引入，不是让对方替你内部推销。

```text
了解。如果方便，您把负责这块的技术或采购同事拉个小群，我把需要确认的三项信息一次说清楚。
```

## 交期不行

先确认必须到货时间、地点和不可替代条件。只有真实商业证据支持时才能给新交期。

```text
收到，您最晚需要哪天到货、到哪个城市？我先按这个硬节点核实可行方案，没确认前不先给您口头承诺。
```

## 长期不回复

只有出现新价值、新事实或已约定节点时再联系。不要发送“在吗”“考虑得怎么样了”。

可用触发：客户要求的价格已确认、配置差异已解决、明确活动或交期变化有官方证据、约定日期到达。没有新触发时，等待或标记暂缓。

## 停止条件

- 明确说不需要、不合作或不要再联系。
- 同一目标连续两次得到弱回应。
- 对方身份或业务明显不匹配。
- 继续沟通需要捏造事实、越权承诺或绕过正式采购流程。
