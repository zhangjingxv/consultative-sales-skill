# 了解客户与自然联系

目的：更准确地理解客户，找到双方聊得来的话题，并在真实需要出现时提供合适的业务帮助。一次交流可以只是交流，不要求每次换来需求或订单。

## 已知内容怎么用

可用用户提供的客户原话、朋友圈文字/截图、此前交往，以及用户明确授权访问且当前工具实际可读的内容。引用可见事实并保留时间；截图裁切、日期或发布者不清楚时标未知。不要声称看过未读到的朋友圈，工具不可用时可基于用户提供的片段工作。

朋友圈可见不代表内容公开，也不代表客户同意被公开引用。真实截图、客户姓名、聊天原文和客户记录不进入公共 Skill 或测试；无需重复外传给模型服务。只读用户指定对象和范围，不扩展为遍历好友或持续监控。

## 四步选话题

1. **可见事实**：客户具体分享了什么？是否近期、是否能确认属于本人？
2. **关系适配**：此前聊过吗，联系频率和对方反应如何，当前有没有事故、投诉或联系限制？
3. **自然切口**：选择一件真实细节，表达具体的关心、祝贺或好奇；不了解就坦诚请教，不假装有共同经历。
4. **顺着回应走**：对方愿意继续就聊；只有对方提到业务问题、接受帮助或存在明确相关事项时再转业务。无需每次补一句“顺便有需求找我”。

优先使用主动分享的职业动态、公开活动和非敏感兴趣。不要从照片、头像、消费或家人信息推断预算、性格、健康、感情状态或购买意愿；也不把脆弱处当成促单手段。敏感经历只有对方当前主动谈起且希望支持时才回应，不主动翻出作销售话题。

## 合成例子

**平常聊过跑步，客户刚发“第一次完成半马”。**

可以说：“第一次半马就跑下来了，恭喜！最后几公里感觉怎么样？”也可以只祝贺，不提问题。
用户没跑过马拉松时，不写“我也跑过同一场”。客户热情聊运动不证明有采购项目。

**客户分享“新办公室终于搬完”，项目情况未知。**

先自然回应：“新办公室收拾好了，恭喜搬家！这段时间应该忙了不少。”不要直接断言需要新服务器。
若客户随后说“业务系统搬过去后不稳定”，再问一个能决定是否提供帮助的问题：“现在主要是访问慢，还是经常断开？”技术原因仍待验证。

**客户已经拒绝产品推荐，但仍愿意聊共同爱好。**

在正常来往范围内可回应爱好，不夹带新品、优惠或邀约。若说的是“不要再联系我”，则停止联系，不用点赞、评论或换账号绕过。

## 私有客户小卡（需要连续跟进时）

只整理对当前沟通有用的信息，不逐项盘问：

| 字段 | 记录方式 |
|---|---|
| 联系人/组织角色 | 已确认身份与职责；未知照实保留 |
| 客户正在做的事 | 对方原意的简短摘要、来源和日期 |
| 当前业务关注 | 已确认需求、约束、参与方、待验证假设 |
| 沟通偏好与话题 | 对方主动表达或实际互动支持的偏好，记录联系边界 |
| 待办与反馈 | 谁答应了什么、何时更新、客户实际后续动作 |

用户提供新回应时更新相关事实，不把旧推测越记越真。需要保存时用用户指定的私有客户记录，避免收集无关家庭或行踪资料；未保存时不得声称已跨会话记住。脱敏复盘只提炼通用方法，不把客户原话搬入公开包。

看两条结果线：关系上是否出现自愿的双向交流、信任和真实信息；业务上是否完成需求确认、验证、采购下一步或订单。点赞、客套、已读和下单分别记录，不互相替代。
