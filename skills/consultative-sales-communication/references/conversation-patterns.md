# 沟通表达范式

这些是结构范式，不是固定文案。使用客户原话、项目事实和用户自己的语气改写。

## 1. 确认业务匹配

```text
X总，想先确认一下，您这边主要做项目集成／客户方案，还是偏渠道供货？
```

只问一个能改变跟进方向的问题，不附带长篇公司介绍。

## 2. 从泛聊进入需求

```text
您刚提到客户最近在扩容。现在最先要解决的是算力、存储容量，还是交付时间？
```

优先找影响方案最大的分叉，不连续盘问全部信息。

## 3. 客户直接问价格但信息不足

```text
可以看价格。为了不报偏，我先确认一个关键点：您要的是整机配置，还是只比这一个部件？
```

确认后再进入核价流程，不给假精确数字。

## 4. 轻量约访

```text
X总，看您这边主要做【已确认业务】，和【相关能力】有交集。
我想过去简单认识一下，了解您常做的项目类型。您看周四下午方便聊20分钟吗？
```

使用具体时间和低成本动作。客户没有表达意愿时，不同时追问地址、参与人和项目清单。

## 5. 确认拜访

```text
那就定周四下午3点。我过去您【已确认地点】，主要把【本次唯一目标】对一下；如果地点有变您提前告诉我。
```

地点未知时只补问地点，不再扩展新话题。

## 6. 接住顾虑并澄清

```text
明白，您担心的是【准确复述顾虑】。
我先确认【一个决定性事实】，再看是补证据、换方案还是先停，不让您反复沟通。
```

## 7. 报价后跟进

有新信息：

```text
X总，上次报价里您关心的【具体问题】已经确认了：【已确认结果】。
您看我按这个口径更新方案，还是先保留原配置？
```

没有新信息：不发空洞催促。

## 8. 礼貌收束

```text
好的X总，那我先不打扰。后面到【真实触发条件】时，您直接发我，我及时配合。
```

不要收束后又追加一个问题。

## 9. 电话开场

```text
X总，我是【身份】。今天想占您几分钟，只确认【本次唯一目标】。如果现在不方便，我按您合适的时间再联系。
```

## 10. 拜访收尾

```text
今天先确认了三件事：【事实1】、【事实2】、【事实3】。
下一步我在【时间】前完成【动作】，您这边由【责任人】确认【动作】。还有没对齐的我先标未知，不先替您做决定。
```

## 11. 快速回复输出

用户只问“怎么回”时：

```text
判断：现在发。

可直接发送：
【1至3个短段落】
```

不要把内部分析混进客户可见文本。

## 12. 复盘输出

```text
客户原话：……
已确认事实：……
销售推测：……
有效动作：……
风险点：……
下次唯一动作：……
建议表达：……
```
