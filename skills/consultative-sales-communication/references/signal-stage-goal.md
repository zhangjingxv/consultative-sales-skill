## 1. 信号判定

不要用单个词或单条消息定性。至少结合最近一轮和已有项目事实。

| 维度 | 弱信号 | 中信号 | 强信号 |
|---|---|---|---|
| 信息量 | 嗯、好的、再说 | 解释业务或原因 | 给场景、数量、节点、参与者 |
| 具体度 | 泛泛了解 | 问产品或能力 | 问明确配置、价格、交期、流程 |
| 回问 | 不回问 | 问一项基本信息 | 连续追问关键条件或下一步 |
| 延伸 | 只答所问 | 补一个相关事实 | 主动发资料、介绍项目或新角色 |
| 承诺动作 | 无 | 表示之后看看 | 发清单、约时间、拉群、确认节点 |
| 阻力 | 不回复或客套 | 忙、已有渠道、需求不明 | 明确拒绝或条件不满足 |

输出示例：

```text
客户信号：中等。依据是客户主动说明了业务类型，但没有项目、时间或下一步动作。
```

不要写成“客户很感兴趣”，除非其行为能直接支持。

## 2. 阶段判定

按已经发生的事实选择最靠后的已闭合阶段，不因销售想成交而跳级。

1. **建立联系**：知道彼此是谁，尚未确认业务交集。
2. **确认匹配**：确认客户业务与自己的能力可能有关联。
3. **发现需求**：出现真实问题、项目或采购可能。
4. **澄清约束**：收集场景、数量、规格、预算、时间、角色和流程。
5. **建立价值**：说明能力如何对应客户问题，并提供适量证据。
6. **方案前共识**：双方同意需要形成某项方案、配置、报价或验证。
7. **处理异议**：存在明确条件差距或风险顾虑。
8. **确认动作**：落实时间、责任人、材料、会议、试用或采购步骤。
9. **暂缓或退出**：当前无匹配、无节点、明确拒绝或连续弱回应。

## 3. 顾虑判定

| 顾虑 | 典型表现 | 优先动作 |
|---|---|---|
| 不相关 | “我们不做这个” | 确认一次业务边界，然后退出 |
| 不理解 | “你们具体做什么” | 用客户语言简述能力，不堆公司介绍 |
| 不信任 | “能做吗”“有案例吗” | 给与当前问题直接相关的真实证据 |
| 不紧迫 | “以后再说”“现在不急” | 找真实触发点；没有则暂缓 |
| 不合适 | “贵”“交期不行”“规格不符” | 澄清比较基准和不可让步条件 |
| 无权限 | “我不负责”“要问领导” | 确认责任角色和引入方式 |
| 有替代 | “有固定供应商” | 判断补位价值，不贬低对手 |
| 信息不足 | 表达含糊或上下文缺失 | 问一个决定性问题，不猜 |

## 4. 本轮目标

只能选择一个主要目标：接住客户情绪或顾虑、确认是否业务匹配、获取一个决定性事实、补充一项有用价值或证据、降低下一步成本、约一个具体时间、确认责任人和动作、礼貌收束并保留真实入口。

选择规则：优先解决会阻断下一阶段的最小问题。例如客户直接问价格但缺少数量和规格，本轮目标是取得最影响价格的决定性事实，而不是先讲一整套产品优势。

## 5. 常见误判

- “收到”“好的”“有需要找你”通常是礼貌收束，不是强意向。
- 客户回复很长可能只是解释拒绝原因，不等于愿意推进。
- 主动问最低价不证明需求已闭合，可能只是市场询价。
- 愿意见面不等于有项目；见面后仍需确认事实。
- 技术人员认可方案不等于采购权限、预算或商务条件已确认。
- 沉默可能来自忙、低优先级、无权、无需求或不信任；没有证据时保持未知。
