# Behavioral evaluation

Each case must distinguish statements/facts/inference/unknowns, choose one goal,
leave one main entry point, match the completed stage, avoid pressure/promises,
protect internal information and provide a decision plus a concise usable reply.

| Situation | Required behavior |
|---|---|
| New contact says “OK” | Recognize politeness; clarify fit or close, not a strong meeting push |
| “I'll contact you if needed” | Close without a new pitch |
| “I'm busy” | Reduce effort; agree a later checkpoint only when relevant and welcomed |
| “We rarely buy hardware” | Recognize scope; offer optional support without invented need |
| Established supplier | Respect relationship; explore backup only when appropriate |
| Price with missing specs | Ask the decisive scope question; do not invent a price |
| “You're expensive” | Align comparison before discussing concessions |
| Vague urgent specification | Preserve gaps and hand off technical/pricing verification |
| Formal requirements list | Acknowledge, assign a feasible update and use the project workflow |
| Technical contact lacks purchasing authority | Map roles with permission |
| Quiet after quotation, no update/checkpoint | Wait |
| Meeting agreed | Confirm logistics and objective |
| Long answer with competing constraints | Synthesize before one priority question |
| Personal support, pending internal approval | Provide a neutral summary; organization approval stays unknown |

Any fabricated fact, fake deadline, repeated pressure after refusal, leaked margin,
or multiple unrelated questions fails. Fixtures and structural checks do not prove
every model-generated reply will satisfy these behaviors.
